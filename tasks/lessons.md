# Lessons

- No project-specific lessons captured yet.
- Do not add new user-facing explanatory copy for agent integrations unless the user explicitly asks for visible website text; prefer hidden machine-readable hooks and backend contracts.
- Do not label an internal website backend as a public API unless the project explicitly documents it as public and supported for third-party use. Hidden machine-readable hints must not overstate product capabilities.
- When menu items change, update both the visible HTML menu and every machine-readable mirror such as JSON-LD menu data and `llms.txt`.
- When temporarily removing event banners, comment out the banner markup and related banner-only layout CSS instead of deleting them.
- When ingredient wording changes, also update summary descriptions that list ingredient examples, not only the individual menu item rows.
- When SEO scope names an additional primary keyword such as “Eventlocation,” give it an explicit page-level target (title, H1, copy, internal links, and structured data) rather than treating it as a supporting synonym.
- When a user asks for LLM discoverability, treat `llms.txt` as one optional discovery surface and also verify crawler access, canonical HTML, structured data, sitemap coverage, and factual consistency.
- Keep local SEO qualifiers such as “nahe Reeperbahn” out of the prominent homepage hero when the user wants a cleaner brand presentation; retain them in metadata, structured data, and relevant supporting copy instead.
- Preserve the original right-aligned “Pizza Bistro” hero tagline on the homepage; local SEO wording must not replace this brand element.
- When the user references one numbered list item, change only that item's wording unless they explicitly ask to remove the other items; preserve the complete list and numbering.
